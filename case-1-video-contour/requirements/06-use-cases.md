# Use Cases - Сценарии взаимодействия видеоконтура

[← к кейсу](../README.md) · [User Stories](05-user-stories.md) · [ER-модель](../data/README.md)

Граница системы видеоконтура платформы Су-Шеф. Основные акторы: автор клуба, зритель и владелец платформы.
Объектное хранилище — внешняя система; воркер и плеер — компоненты системы. Telegram и Max — среды выполнения
одного пользовательского интерфейса. Оплата и выпуск подписки находятся за границей этих сценариев: видеоконтур читает право.

## UC-1. Загрузить и опубликовать видеорецепт

| Параметр | Значение |
|---|---|
| Актор | автор клуба |
| Цель | предоставить зрителям видеорецепт независимо от длительности процесса нарезки (транскодирования) |
| Триггер | автор выбирает видео в редакторе |
| Предусловия | действующая сессия, право автора в выбранном клубе, рецепт принадлежит клубу |
| Результат | опубликованный рецепт доступен по уровню доступа; задача обработки отражает результат нарезки |
| Связи | US-1; FR-3/4; TC-8/9/27; sequence загрузки и state задачи |

Основной поток:

1. Автор выбирает исходный файл и сохраняет рецепт.
2. Система проверяет клуб, роль, лимит 200 МБ и тип по сигнатуре; сохраняет исходник в транзит.
3. Система создаёт задачу PENDING и подтверждает принятие файла. Автор публикует рецепт.
4. Система отдаёт исходник зрителям с правом через защищённый маршрут с Range; приватные пути не раскрываются.
5. Воркер забирает задачу в RUNNING, определяет ориентацию, размер и длительность, формирует доступные профили HLS.
6. После успешной выгрузки HLS воркер сохраняет оригинал приватно, записывает URL плейлиста и переводит задачу в DONE.
7. Система инвалидирует кэш рецепта. Новые открытия используют HLS; активные чтения исходника завершаются,
   после чего транзит удаляется. Оригинал включается в ежедневное резервирование.

Альтернативы:

| Шаг | Условие | Поведение |
|---|---|---|
| 2 | файл превышает лимит или не соответствует типу | ошибка в редакторе; автор выбирает другой файл |
| 5 | воркер недоступен | задача остаётся PENDING, защищённый исходник доступен, срабатывает контроль очереди |
| 5–6 | ошибка обработки/выгрузки | FAILED, причина и число попыток в задаче; исходник сохраняется |
| после ошибки | автор выбирает «Повторить» | сохранённая задача возвращается в PENDING с тем же исходником |
| до сохранения оригинала | потерян транзитный диск | повторная загрузка файла; граница сохранности определена NFR-8 |

Минимальная гарантия: отсутствие успешной HLS-выгрузки не создаёт ложное состояние DONE и ссылку на недоступный плейлист.
Состояние публикации рецепта не подменяет состояние обработки видео.

## UC-2. Привязать фрагмент видео к шагу

| Параметр | Значение |
|---|---|
| Актор | автор клуба |
| Триггер | выбор действия «Фрагмент видео» у шага |
| Предусловия | право редактировать рецепт; основное видео можно воспроизвести в редакторе |
| Результат | границы фрагмента сохранены в JSONB шага, фото и видео не назначены одновременно |
| Связи | US-2; модель шага; TC-21 |

1. Система открывает подборщик основного видео: свежий файл из сессии редактора либо HLS сохранённого рецепта.
2. Автор задаёт `startSec` и `endSec` маркерами или вводом времени; просматривает выбранный фрагмент.
3. Система проверяет целые неотрицательные секунды, `startSec < endSec` и границу длительности видео в подборщике.
4. Автор подтверждает выбор; система назначает `videoSegment` и убирает фото шага.
5. При сохранении рецепта сервер повторно проверяет структуру, порядок границ и взаимное исключение медиатипов.
6. При повторном открытии редактора выбранные границы отображаются у шага.

Если основного видео нет, действие выбора неактивно. Некорректные границы не сохраняются; отмена подборщика сохраняет
прежнее значение. Шаг без фрагмента остаётся текстовым или с фото. При замене видео автор проверяет диапазоны повторно.

## UC-3. Открыть и смотреть рецепт

| Параметр | Значение |
|---|---|
| Актор | Зритель — посетитель, участник или подписчик клуба |
| Триггер | открытие карточки или ссылки на рецепт на сайте, в Telegram или Max |
| Предусловия | домен определяет опубликованный клуб; рецепт существует и доступен по правилу публикации |
| Результат | зритель получает видео по своему праву либо открытое превью и действие оформления доступа |
| Связи | US-3/4/6/7; FR-1/2/5/6/7/8/11; TC-1…20/22/23/27/28/32…37/39 |

1. Система загружает ядро рецепта; вторичные секции догружаются независимо. Общие данные читаются из кэша,
   сессия, клуб и право определяются на запрос.
2. Система применяет матрицу доступа: REGISTERED — участнику клуба; PRO — при действующей подписке;
   автор своего клуба и администратор получают доступ по роли.
3. При праве на видео система показывает постер и инициализирует плеер.
4. Для готового HLS плеер запрашивает master и плейлист качества. Каждый запрос проходит проверку сессии, лимита,
   клуба, публикации и права. Плейлист качества содержит ссылки на сегменты с TTL 900 с для зрителя.
5. Плеер получает сегменты напрямую из хранилища, адаптирует качество по каналу. Зритель может выбрать качество вручную.
6. После истечения ссылок, в том числе при длительной паузе, плеер перезапрашивает плейлист и продолжает с прежней позиции.
7. Плеер отправляет события старта, буферизации и ошибок; отправка метрик не задерживает воспроизведение.

Альтернативы:

| Шаг | Условие | Поведение |
|---|---|---|
| 1 | неизвестный клуб, отсутствующий/неопубликованный рецепт | страница не найдена; медиа не выдаётся |
| 2 | нет права на уровень рецепта с подпиской "PRO" | открытое превью и переход к тарифам; видео и фото шагов исключены из выдачи |
| 3–4 | HLS ещё не готов | защищённая выдача исходника по UC-1; автоматического выбора профиля до HLS нет |
| 4/6 | сессия отсутствует/истекла | 401; вход с сохранением контекста рецепта |
| 4/6 | право отсутствует/закончилось | 403; постер и действие оформления; новая ссылка не выдаётся |
| 4 | превышен лимит | 429; запрос не обходит контроль права |
| 4 | плейлист не найден | 404; диагностическое событие без подписи |
| 4/6 | сбой проверки или хранилища | 5xx без выдачи доступа; локальная ошибка видео не блокирует текст рецепта |

Обновление ссылки повторяет тот же контроль доступа, независимо от попадания в кэш. Уже полученные байты не отзываются.
Платёжный сценарий начинается после перехода к тарифам и не входит в UC-3.

## UC-4. Готовить по шагам

| Параметр | Значение |
|---|---|
| Актор | зритель с правом на рецепт |
| Триггер | действие «Готовить» на странице рецепта |
| Предусловия | рецепт содержит шаги; право подтверждено по UC-3 |
| Результат | зритель проходит шаги и возвращается на страницу рецепта |
| Связи | US-5; FR-9/10/12; TC-29…31/36 |

1. Система открывает первый шаг и его текст. Если задан `videoSegment`, запускает основное видео с `startSec`.
2. На `endSec` система останавливает видео и предлагает повтор фрагмента с начальной границы.
3. Зритель переходит вперёд/назад кнопкой либо свайпом; система синхронно меняет текст и медиапредставление.
4. На новом шаге фрагмент запускается с его начальной границы. Если фрагмента нет, отображаются текст и фото при наличии.
5. На первом шаге переход назад недоступен. На последнем вместо «Вперёд» показано «Завершить готовку».
6. Завершение возвращает зрителя на страницу рецепта. Для одного шага одновременно действуют оба граничных правила.

При истечении TTL выполняется обновление по UC-3 с сохранением номера шага и позиции. При 401 предлагается вход,
при 403 — оформление доступа; защищённые медиа повторно не выдаются. Пауза не переключает шаг автоматически.

## UC-5. Восстановить видеорецепт

| Параметр | Значение |
|---|---|
| Актор | владелец платформы |
| Триггер | утрата производных файлов либо инцидент основного хранилища/сервера |
| Предусловия | владелец имеет доступ к защищённым копиям; известны клуб и рецепт |
| Результат | оригинал восстановлен, HLS сформирован, просмотр по праву доступен |
| Связи | US-8; BR-6; NFR-8/9/10; TC-24…26/38 |

1. Владедец определяет масштаб утраты и фиксирует время начала восстановления.
2. Если потерян только HLS, система использует приватный оригинал; при потере оригинала оператор выбирает последнюю
   защищённую резервную копию и сверяет её время с RPO ≤ 24 ч.
3. Оператор восстанавливает оригинал в нужный клубный префикс и запускает задачу нарезки.
4. После DONE система обновляет ссылку и инвалидирует кэш рецепта.
5. Оператор проверяет просмотр с правом и отказ без права, фиксирует время восстановления по NFR-10.

Отсутствие нужной копии или ошибка нарезки не считаются успешным завершением: инцидент остаётся открыт,
причина фиксируется, оператор выбирает другую защищённую версию или повторяет обработку. Учение выполняется
в изолированных ресурсах без удаления объектов действующих клубов.
