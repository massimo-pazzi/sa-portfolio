# Логическая модель данных концепции

[← к кейсу](../README.md) · [ER-модель](../diagrams/er-model.png) · [исходник](../diagrams/er-model.mmd)

Это предметная модель концепции, а не физическая схема внедрённой БД. Имена и состав атрибутов приведены
для объяснения связей; типы хранилищ и внешние ключи уточняются при аудите источников.

| Сущность | Назначение | Ключевые связи |
|---|---|---|
| Дом | общий контекст паспорта и адреса | дом содержит 0…N инженерных систем |
| Инженерная система дома | отопление, водоснабжение, лифты, электрика | принадлежит ровно одному дому; объединяет оборудование, заявки и прогнозы |
| Оборудование | конкретный объект с типом, наработкой и историей обслуживания | относится к системе дома; детализация существует там, где есть паспортные данные |
| Заявка | зафиксированное обращение о неисправности | относится к системе дома, имеет время события и категорию |
| Прогноз | сигнал о возможном аварийном обращении в горизонте | относится к системе дома; содержит время расчёта и объяснение |
| Решение инженера | принятие или отклонение прогноза | относится ровно к одному сигналу; история решений не подменяет исходный прогноз |
| Наряд | назначенная работа с основанием и результатом | относится к системе дома; оборудование, прогноз и бригада — опциональные связи |
| Бригада | исполнитель со специализацией | у бригады 0…N нарядов, у наряда до назначения бригады нет |

## Инварианты

1. Заявка, прогноз и наряд не сопоставляются только по тексту адреса: нужен согласованный идентификатор дома и тип системы.
2. Оборудование наряда, если оно задано, относится к той же системе дома. Неизвестный объект оборудования не заменяется догадкой.
3. У каждого наряда есть время создания и одно основание: прогноз, осмотр, календарный график либо заявка.
   Ссылка на прогноз обязательна для основания «прогноз»; для остальных оснований она не требуется.
4. Прогноз является рекомендацией, а не подтвержденной аварией. Принятие инженером не означает, что авария уже произошла.
5. Календарное обслуживание не засчитывается как превентивная работа по сигналу.
6. Вероятность, горизонт и объяснение относятся к одному расчёту; нельзя подставлять объяснение от более позднего сигнала.

На диаграмме наряд связан только с прогнозом как одним из оснований; остальные основания заданы атрибутом `source`.
Полный справочник оснований, телеметрия и мониторинг уборки за пределами этого фрагмента.
Сущности и смысл атрибутов выведены из разделов исходной концепции о пользователях, метриках, прогнозе и прототипе.
