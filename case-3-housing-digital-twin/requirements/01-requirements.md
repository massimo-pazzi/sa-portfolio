# Требования и пользовательские сценарии

[← к кейсу](../README.md) · [приёмка](../tests/acceptance.md)

Выдержки требований концепции. Формулировки описывают проектируемое поведение; потребности диспетчера и инженера проверяются на предпроектном этапе.

## Бизнес-требования

| ID | Требование | Проверка ценности |
|---|---|---|
| BR-1 | Объединить сведения о доме и его инженерных системах | пользователь находит паспорт, оборудование, обращения жителей и историю работ в одном контексте |
| BR-2 | Поддержать выбор превентивных работ до аварийного обращения | инженер получает приоритетный список объектов для проведения приветивного ремонта с обоснованием и принимает решение |
| BR-3 | Обеспечить прослеживаемость от основания работы до наряда | результат можно связать с прогнозом, осмотром, графиком либо заявкой |
| BR-4 | Дать территориальному руководству контроль уборки территории | план/факт маршрута, простои и покрытие по участку территории |
| BR-5 | Проверить полезность прогноза до масштабирования | ретроспективный тест превосходит простое правило по согласованному критерию |

## User Stories

| ID | История | Критерий приёмки |
|---|---|---|
| US-1 | Как инженер, хочу увидеть историю и объяснение риска, чтобы выбрать объект для осмотра | карточка и сигнал относятся к одной системе дома; источник и горизонт риска видны |
| US-2 | Как инженер, хочу принять или отклонить прогноз, чтобы назначение работы оставалось моим решением | решение сохранено; наряд связан с принятым прогнозом |
| US-3 | Как диспетчер, хочу видеть срочность заявки и специализацию бригад, чтобы спланировать исполнение | заявки доступны по категории/приоритету, подходящие бригады — по специализации |
| US-4 | Как руководитель, хочу видеть план и факт уборки, чтобы проверить выполнение по участку | показаны отклонения, простои и покрытие; отсутствие трека не выдаётся за выполненную уборку |
| US-5 | Как заказчик, хочу сравнить модель с простым правилом, чтобы принять решение о пилоте | тест использует будущий период, одинаковый список объектов и заранее выбранный порог |

## UC-1. Рассмотреть прогноз и назначить работу

**Актор:** инженер. **Триггер:** открытие списка рисков. **Предусловия:** объект сопоставлен с системой дома,
для него сформирован сигнал с горизонтом. **Результат:** решение сохранено; при принятии создан наряд с основанием.

1. Инженер открывает приоритетный список рисков и выбирает сигнал.
2. Система показывает дом, систему, доступное оборудование, историю обращений/ремонтов и объяснение риска.
3. Инженер оценивает контекст и принимает прогноз.
4. Система сохраняет решение и предлагает создать превентивный наряд.
5. Инженер подтверждает создание; наряд сохраняет объект, систему, время, источник «прогноз» и ссылку на сигнал.
6. Наряд доступен диспетчеру для планирования бригады. Последующее исполнение учитывается в метриках.

**Альтернативы:**

- Инженер отклоняет сигнал: решение сохраняется, автоматического назначения бригады нет.
- Нет привязки к оборудованию: работа относится к системе дома, серийный номер не подставляется предположительно.
- Источники неполны: интерфейс показывает ограниченность данных; отсутствие телеметрии не означает низкий риск.
- На момент создания уже есть аварийная заявка по той же системе: наряд не считается превентивным только из-за
  наличия ссылки на прогноз; применяется определение метрики по времени событий.

## UC-2. Проверить уборку участка

**Актор:** руководитель территориальной службы. **Триггер:** выбор участка и периода.
**Предусловия:** доступны план маршрута и фактические GPS-наблюдения. **Результат:** видны выполнение, отклонения и простои.

1. Пользователь выбирает участок и период на карте.
2. Система показывает плановый маршрут и фактический трек, покрытие и отклонения.
3. Пользователь рассматривает участки простоя и непокрытую площадь.
4. По результату принимает управленческое решение; отметка на карте сама по себе не является актом приёмки уборки.

При отсутствии фактического трека система показывает отсутствие данных. Фото до/после и учёт уборочной техники
относятся к развитию модуля; автоматическое подтверждение качества уборки по GPS не предполагается.
